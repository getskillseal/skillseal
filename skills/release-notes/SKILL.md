# Release Notes

Turn a list of merged pull requests into clean, categorized release notes.

## Instructions

1. Group the changes into Features, Fixes, and Maintenance.
2. Write one bullet per change in the past tense, user-facing language.
3. Omit internal refactors unless they change behavior.
4. Put breaking changes first, under a bold "Breaking" heading.
5. Keep it to one screen. Link each bullet to its pull request.
